# Changelog

All notable changes to the Pickleball Haven Booker will be documented in this file.

## [0.1.0.3] - 2026-09-02

Findings from a code review of 0.1.0.2. Three of them are backed by this
skill's own captured pages under `debug/uncertain_*` rather than by inference.

### Fixed
- **The card collector could attach one card's text to another card's button.** The DOM walk stopped at a card-level container only when that container's text contained "OPEN PLAY"; otherwise it kept climbing. A Clinic card inside a `card-deck` therefore fell through to the deck, whose aggregate `innerText` carries the date, time range and `FREE` of the *sibling* Open Play cards — so every downstream check passed on borrowed text and the booker clicked the Clinic's Register button. The climb now abandons a button as soon as it reaches an ancestor holding a second Register/Withdraw button, because that ancestor is a multi-card wrapper. The test that nominally covered this only grepped the JS for two string literals and never exercised the traversal.
- **Free sessions were dropped when the price rendered inline.** `_card_is_free` required a line reading exactly `FREE`. CourtReserve's own captured page (`debug/uncertain_2026-08-30T18-42-03`, line 3) renders `Sat, Aug 1st  9a - 12p  FREE` as one block, which parsed as paid — the card was dropped and the run returned `none_available` for a session that was free and bookable. Fee detection now works in three tiers: a line reading only `FREE` (tolerating `Free!` / `(FREE)`) is CourtReserve's price field and outranks a dollar amount in the human-written title; an inline `FREE` counts only on a card carrying no positive price anywhere; any remaining `$N` above zero marks the card paid. The middle tier is deliberately narrow — matching a bare `FREE` anywhere unconditionally makes `$12.00 per player - includes FREE paddle rental` look free, which is the 0.1.0.2 bug returning by another route. A card with *no* price information at all is still treated as paid; that stays fail-closed, and the `none_available` message now names the fee check so the drop is visible.
- **CourtReserve's actual confirmation string wasn't in the keyword list.** `debug/uncertain_2026-08-30T19-54-46` line 72 reads `Registration successful.` on the post-booking page — and that run was classified `uncertain`, which is why the snapshot exists. Neither `SUCCESSFULLY REGISTERED` nor `REGISTRATION COMPLETE` is a substring of it. `REGISTRATION SUCCESSFUL` added.
- **Non-bookable registration states were treated as available.** Broadening the collector's filter to `/REGIST|WITHDRAW/` in 0.1.0.2 also admitted "Registration Closed", "Registration Full", "Waitlist Registration" and "View Registrations". None are in `REGISTERED_BUTTON_TEXTS`, so they counted as unbooked, and since only the top-ranked session is ever attempted, one of them winning the sort meant a genuinely bookable session further down was never tried. Button state is now classified by `_classify_button`.
- **Registered-state detection used exact equality on raw `innerText`.** The collector matched by substring but classification demanded the label equal `EDIT REGISTRATION` exactly — so an icon glyph, a wrapped span (`EDIT\nREGISTRATION`) or a non-breaking space made an already-held session look unbooked and got it re-registered, and stopped the post-booking check from recognising its own card. Matching is now by word on a normalised label. Same substring-vs-exact class of bug as the 0.1.0.2 "REGISTER is not in REGISTRATION" fix.
- **Asking for a slot you already hold booked a second, overlapping one.** `already_booked` fired only when *every* qualifying session was held. With the ±45-minute window a 9:00 request the owner already had fell through to 9:15 and registered that too, reported as "🎾 Booked you into the 9:15 session"; with no `--target-time`, an owner holding 7 AM got 9 AM. The check now asks whether the *requested* (top-ranked) session is held.
- **A page read racing a navigation turned a completed booking into `error`.** `page.inner_text("body")` and `page.url` sat outside every `try`. CourtReserve redirects to `/Portal/Index?forceDashboard=True` after finalize, so a call against a page mid-navigation raised, escaped to the catch-all in `book_pickleball_session`, and returned "Booking site behaved unexpectedly" for a booking that went through — with no snapshot written. SKILL.md relays `error` verbatim and `preferences.json` sets `auto_confirm: true`, so the owner's natural retry booked the slot twice. Both reads are now guarded so classification continues to the events-list check.
- **The meridiem in the time pattern wasn't word-anchored.** `(?:am|pm|a|p)` matched the `2 p` of "2 players per court" and the `4 a` of "4 available", so a card reading "50 of 50 spots remaining / 2 players per court" parsed as a 2 PM session and was offered to the owner. `_parse_start_time` had the same gap plus an ordered alternation that matched the `A` of "9 April", and used `search` rather than `fullmatch`, so "after 5" parsed as 5:00 AM despite 0.1.0.2's claim that unreadable target times error out.
- **The registration form filler clicked every visible checkbox.** No allowlist, so an "Add a guest" / "Bring a partner" / marketing opt-in box on the same form got ticked on a session the fee check had cleared as FREE, and nothing downstream re-reads the fee. Money- and marketing-shaped checkboxes are now screened out unless the form marks them required, and skipped ones are logged to stderr.
- **The reconfirmation probe read an unfiltered events list.** The main flow clicks the Today / Tomorrow sidebar radio precisely because the default view does not reliably render those cards, but `_confirm_on_events_list` reproduced neither click — so a same-day or next-day booking could be confirmed against a view without its card and fall through to `uncertain`. The probe now applies the same filter.
- **`_registered_state_for_session` was missing the empty-date guard its sibling has.** `_card_date_pattern("")` compiled to `\b\s+(?:st|nd|rd|th)?\b`, which matches every run of whitespace in every card, so a caller with no date confirmed a booking against an arbitrary card. The guard moved into the function itself, and an empty date now compiles to a pattern that matches nothing.
- **`--dry-run` hard-failed on a booking-only field.** `SELF_RATED_LEVEL` was validated before the dry-run branch, so "what's available tomorrow?" returned a seven-option configuration dump. It is now checked on the booking path only.
- **The booker never read `preferences.json`.** The 0.1.0.2 note said the tier "lives in `preferences.json` alone and is enforced by the booker"; the booker actually read `MEMBERSHIP_TYPE` from `.env` and defaulted to AM. On a fresh checkout — where `preferences.json` is `.gitignore`d and absent — a FULL member silently got the AM window and "No free Open Play sessions found for your AM membership (12:00 AM - 2:30 PM)" for every evening request. `preferences.json` now wins, `.env` is the fallback, and neither set is an error rather than a guess.
- **`none_available` always blamed the membership tier.** Five separate filters drop cards and all of them produced "No free Open Play sessions found for your {tier} membership ({window})" — which for a FULL member reads "for your FULL membership (all day)", naming an all-day window as the reason nothing was found. The message now names the filter that actually fired.

### Changed
- Card collection got roughly 5x cheaper on the unfiltered events list. The multi-card-wrapper guard counted action buttons on *every* ancestor of every button; on the 205-card unfiltered view that is on the order of half a million node visits. It now counts only on card-level ancestors, which are the only containers the walk can settle on — same guarantee, a fraction of the work.
- The registered-state pattern is derived from `REGISTERED_BUTTON_TEXTS` instead of restating those three labels in a second place, so the tuple the tests assert against is the only definition and a new label starts classifying without a second edit.
- Two test assertions could not fail and were replaced: `test_scan_makes_one_round_trip_per_page` checked the whole function for the literal `"inner_text()"`, which never appears with or without the bug, and `test_collect_js_does_not_use_unbounded_walk` grepped the JS for two strings. They now assert on the card loop and on the traversal's actual bound.
- Error paths on the new helpers are covered rather than assumed: a missing, malformed, non-dict or blank-tier `preferences.json`; an unreadable button label; a malformed card date; a `none_available` with no filter to name; and a missing Today/Tomorrow sidebar radio. Each of these fails toward "carry on", so an untested one fails silently by design.
- The test module seeds `SELF_RATED_LEVEL` and blanks `preferences.json` where it drives the tier through `MEMBERSHIP_TYPE`. Without the first, the tier tests only passed on a machine whose real `.env` supplied a level; without the second they were silently testing the developer's own FULL tier. One new test was reaching CourtReserve over the network — the suite runs offline again.

## [0.1.0.2] - 2026-08-30

### Fixed
- **A failed booking could report `booked`.** Confirmation was decided by substring-matching the whole page against a keyword list containing `WITHDRAW`, `REGISTERED` and `COMPLETE`. The events list shows a Withdraw button for *every* session you already hold, so once you had one booking that week a later failed attempt returned `booked`; a dashboard reading "Complete your profile" did the same. Confirmation now requires unambiguous copy, or a registered-state button on the card for *this* session's own date and start time, and never fires while the page is still sitting on the sign-up form.
- **Paid sessions could be booked as free.** The fee check required a whole line to fullmatch `$12.00`, so `$12.00 per player`, `$12 (Member)` and `Fee: $12.00` all parsed as free. It also read a bare trailing number — a spots-remaining count — as a fee and silently dropped free sessions. An explicit `FREE` price field now wins outright — it is priced for the logged-in account, so the live `$10 HAPPY HOUR OPEN PLAY` card (a `$10` non-member rate in its title, `FREE` in the price field because the membership covers it) stays bookable. Otherwise any `$N` above zero marks the card paid.
- **A single-digit target date matched double-digit cards.** `card_date_str` was substring-tested, and `Aug 1` is inside `Aug 12th`, so a booking for the 1st could match cards for the 10th-19th. Day numbers are now anchored and the ordinal suffix is matched explicitly.
- **"NO OPEN PLAY" and Special Event cards were treated as bookable Open Play.** Same substring trap as the 0.1.0.1 Beginner fix: on 2026-08-30 the only card on the page was `Haven Cup *Tournament Players & Spectators* - NO OPEN PLAY`, which contains `OPEN PLAY` and would have been booked. Card eligibility moved into `_is_open_play_card()`.
- **The Self-Rated Level setter reported success it never verified.** `kendoDropDownList.value()` silently no-ops when the argument isn't in a loaded dataSource, but the JS returned `"set"` unconditionally — so the `uncertain` branch showed the generic message and pointed away from the real cause. The value is now read back, falls back to selecting by rendered text, and the internal reason code stays on stderr instead of reaching the user.
- **An unreadable `--target-time` silently booked the earliest slot.** A value the time parser couldn't read left the proximity filter switched off, so the first session of the day won the sort — "book me tonight" landed on 7 AM. The agent builds this string from natural language, so it is now validated: an unreadable time returns `error` before a browser is launched, and out-of-range clock values (`25:00`, `13 PM`, `9:75`) no longer parse.
- **Session times were read from the human-written card title.** `_extract_session_time` took the first range anywhere in the card, which is usually the title — and titles round (`Open Play/Challenge Courts 9AM - 12PM` for a 9:15 session, the shape that caused the 0.1.0.1 mis-book) or carry unrelated numbers (`$10 HAPPY HOUR OPEN PLAY (12-2:30 PM)`). The range CourtReserve prints after the date is now authoritative, with the title kept only as a fallback. Reported slot times are consistent as a side effect.

- **Already-registered cards were invisible to the scanner.** Found by running a real booking on 2026-08-30: `"REGISTER"` is not a substring of `"REGISTRATION"` (`REGIST-R-ATION`, no second E), so a label filter built on it dropped every "Edit Registration" and "Cancel Registration" card. `already_booked` could never fire, and a successful booking reported `uncertain` because the post-booking check couldn't find its own card. (Introduced by the batched-scan change in this same release; the Playwright `has-text` selector it replaced had matched correctly.)
- **The events-list reconfirmation runs in its own tab.** Navigating the main page to re-read the events list destroyed the post-booking snapshot — the post-mortem then captured the events list rather than the page we'd failed to classify, which is the one piece of evidence every diagnosis in this skill has come from. A second tab keeps the landing page intact, and means the snapshot is written only when the booking is genuinely uncertain rather than on every success (CourtReserve bounces to the dashboard either way).
- **Confirmation now re-reads the events list instead of classifying the landing page.** A real booking on 2026-08-30 finalized correctly — spots went 49 to 48 — and then bounced to `/Online/Portal/Index?forceDashboard=True`, exactly as on 2026-06-03. No amount of keyword tuning classifies a dashboard. When the landing page is inconclusive the booker now navigates back to the events list and reads this session's own card, which is the same check a human would make.
- **An absent Self-Rated Level field was reported as a failure.** Most Open Play events have no such field; `not-present` is normal and no longer produces "the Self-Rated Level field couldn't be set automatically", which sent the reader after a non-existent problem.

- **`login_failed` was undocumented.** The booker can return it, but SKILL.md listed neither it nor `dry_run` as terminal statuses — and SKILL.md's own rule is that a non-terminal status means "poll again", which is the silent no-reply failure mode. Both are documented now, with reply guidance, and a test asserts the code and SKILL.md can't drift apart again.

### Changed
- SKILL.md's "Time-of-day → slot mapping" no longer hardcodes AM/PM tier windows. It described AM tier — instructing the agent to reply "AM tier is closed for today" after 2:30 PM — while `preferences.json` had recorded `FULL` (every slot, 7 AM – 10 PM) since 2026-06-07. Tier now lives in `preferences.json` alone and is enforced by the booker, so the two can't contradict each other. When `preferences.json` is absent the agent asks rather than assuming a tier.
- Card scanning makes one browser round trip per page instead of two per card (`_collect_session_cards`), and the card-parsing rules it shares with the post-booking confirmation check now live in tested pure functions.
- Time-range parsing no longer uses the character class `[-–—to]+`, which matched a stray `t` or `o` between two times.

## [0.1.0.1] - 2026-07-31

### Fixed
- Card scan matched any text containing "OPEN PLAY", which also matches "Beginner Open Play". On 2026-07-31 a 9:00 AM request booked the Beginner session instead of the regular one because it sorted closer to the target time. Cards containing "BEGINNER" are now excluded outright.

## [0.1.0.0] - 2026-04-04

### Added
- Multi-membership support: AM, PM, and Full Day tiers. Set `MEMBERSHIP_TYPE` in `.env`.
- Pre-scan validation catches tier/time conflicts before launching the browser.
- Tier-aware error messages include your membership window when no sessions match.
- `.env.example` template with all configuration fields documented.
- 37 unit tests covering all tier filtering logic, validation, and edge cases.

### Changed
- `_load_env()` now always parses `.env` for non-credential config, even when credentials come from Keychain.
- `_is_before_cutoff()` replaced with `_is_within_tier_window()` supporting all three tiers.
- FULL tier skips time filtering entirely instead of using a fake all-day window.
- Invalid `MEMBERSHIP_TYPE` returns a clear error instead of silently defaulting to AM.
- SKILL.md and README.md updated for multi-tier documentation.
